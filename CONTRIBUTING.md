# Contributing to IndicSpec

Thanks for your interest. IndicSpec is a measurement project, so the bar for a contribution is simple:
**every number must be reproducible from a command, and every claim must point to its evidence.**

## Ways to help

| You want to… | Start here |
|---|---|
| Report a bug or a number that does not reproduce | [Bug report](https://github.com/pratx1906/indicspec/issues/new?template=bug_report.yml) |
| Evaluate a new drafter (EAGLE variant, DFlash successor, MTP head, n-gram method) | [New drafter](https://github.com/pratx1906/indicspec/issues/new?template=new_drafter.yml) |
| Add a language or a benchmark source | [New language](https://github.com/pratx1906/indicspec/issues/new?template=new_language.yml) |
| Native speaker of ta / te / kn / ml / hi willing to review prompts | open an issue titled `Native-speaker review: <language>` |

## Development setup

```bash
# CPU environment (Linux, macOS, WSL; Windows works for everything except the engines)
uv sync --extra analysis --extra data
make test        # unit + property tests, the same subset CI runs
make lint        # ruff check, ruff format --check, mypy
make data        # rebuild the benchmark and verify checksums (downloads ~70 MB)
make figures     # regenerate docs/assets/*.svg from results/tables
```

GPU work (vLLM / SGLang) runs inside Linux or WSL2 in separate virtual environments:
`bash env/install_engines.sh all`, then `bash scripts/smoke.sh <engine> <arm> <model>`.
See [`env/ENGINES.md`](env/ENGINES.md).

## Ground rules

1. **Evidence over assertion.** A number in code, docs or a figure must trace to a raw log in `results/raw/`
   or a source listed in [`docs/CLAIMS.md`](docs/CLAIMS.md) with its status (`OPENED`, `EXCERPT-ONLY`,
   `SELF-REPORTED`, `MEASURED`, …). Add a row when you add a claim.
2. **Raw results are append-only.** Never hand-edit `results/raw/`; tables and figures are regenerated by scripts.
3. **Pre-registration wins.** Confirmatory thresholds live in [`docs/PREREG.md`](docs/PREREG.md) and are frozen in
   git before the runs they govern. Anything else is labelled *exploratory*.
4. **Fair baselines.** A new arm needs a smoke run, an English configuration check against its authors' reported
   behaviour, and the same memory and concurrency policy as every other arm.
5. **Pin everything.** Model, drafter and dataset revisions go in `configs/`; engine versions in `configs/engines.yaml`.
6. **Licences.** Check the licence of any dataset or checkpoint before adding it; ship builders and checksums,
   not third-party text.
7. **GPU safety.** Never pass CPU-offload or swap options to an engine; the VRAM guard must stay on.

## Adding a drafter (arm)

1. Pin the checkpoint in `configs/arms.yaml` (`drafters:` with repo + revision).
2. Add the arm's engine flags under `arms:` for each engine that supports it.
3. Run `bash scripts/smoke.sh vllm <ARM> <model>` (and `sglang`); `python -m indicspec.analysis.engine_status`
   regenerates the status table.
4. Run the English probe (`scripts/probe_en.sh` pattern) and compare with the authors' reported acceptance.
5. If an engine cannot load it faithfully, document *why* in [`docs/ENGINE_STATUS.md`](docs/ENGINE_STATUS.md)
   rather than converting it into something different.

## Adding a language

1. Add the language code and its Unicode block to `src/indicspec/tokens/classes.py` (`SCRIPT_BLOCKS`,
   `LANG_SCRIPT`) with a test in `tests/unit/test_token_classes.py`.
2. Add sources to `configs/data_sources.yaml`; items should be parallel with the existing languages.
3. `make data` must reproduce identical checksums twice in a row.

## Pull requests

Small, focused PRs with passing `make test` and `make lint`. Fill in the PR template; for anything that changes a
reported number, include the command that reproduces it and the raw log path.

By participating you agree to the [Code of Conduct](CODE_OF_CONDUCT.md).
